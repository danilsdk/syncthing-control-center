# Review SCC

Работай без изменения исходников, если исправления не поручены отдельно.
Прочитай карточку и её журнал, контракт и инструкции соответствующих каталогов.

- Рассмотри полный diff задачи относительно актуальной базовой ветки.
  Для чужого PR ориентируйся на ID карточки, а не на свою роль участника.
- Проверь границы изменений по принятой политике, включая старые имена при rename.
  Изменение allow, CI или самих проверок требует содержательного review.
- Проверь существенные сценарии: время и выключенные правила, устаревшая команда,
  недоступность, неподтверждённый HTTP-успех, пропуски наблюдений, нулевой знаменатель.
  Читай только пункты, применимые к рассматриваемому модулю.
- Сопоставь заявленное поведение с проверками. Не считай mock или зелёный harness
  доказательством работы реального Syncthing. При необходимости запусти существующие
  проверки в рабочей папке PR без редактирования кода.
- Сообщи только конкретные дефекты с местом, сценарием и последствием; отдельно
  перечисли существенные непроверенные части. Если дефектов не найдено, скажи это.
- Передай результат в текущем чате. Комментарий в GitHub, сообщение другому агенту
  или слияние выполняй только по прямому поручению человека.
