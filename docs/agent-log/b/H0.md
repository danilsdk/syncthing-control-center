## Получившееся поведение

Закреплены роли: danilsdk — автоматизация/интерфейс, playerboom — интеграция/данные.
Карточки задают точную область записи, собственную ветку и критерии готовности.
Harness создаёт отдельные worktree, проверяет изменения и сохраняет контекст задачи.
Включены локальные hooks; подготовлены CI, CODEOWNERS и запрос review напарника.

## Решения

- Python 3.10+ и Git без сторонних зависимостей для базового harness.
- JSON-карточки отделены по задачам; общие продуктовые файлы ведёт A, harness — B.
- Backend/Frontend-конфигурации проверки разделены по владельцам.
- В CI границы diff проверяются по карточке базовой ветки. Первый H0 допускает
  bootstrap, поскольку в исходном main harness ещё отсутствует.
- Review workflow запускает только доверенный код базовой ветки с write-токеном.
- Единого изменяемого журнала нет; каждой задаче соответствует отдельный файл.
- A4 сдаёт основной стенд до B4; B4 использует принятый стенд для UI E2E.
- По поручению пользователя 2026-10-15 активный агент напарника вправе проверять,
  одобрять и объединять подходящие PR без повторного вопроса, включая первый H0.
- Политика в `.harness/merge-policy.json`, read-only команда `review-plan` фиксирует
  head/base и проверяет origin, автора, напарника, принятую карточку и свежесть базы.
  Полный review, фактический CI и merge остаются отдельными действиями агента.

## Применённая защита main — 2026-10-15

- Обязательный `validate` только от GitHub Actions, app_id 15368.
- Требуется актуальная базовая ветка, один approval и одобрение последнего push
  другим аккаунтом. Устаревшие approvals отменяются, обсуждения должны быть закрыты.
- Требования действуют и для администратора; force push и удаление main запрещены.
- Настройки записаны и повторно прочитаны через GitHub API. Права участников и
  авторизация друга не менялись. Начальный PR не объединялся этой сессией.

### Изменения

1. Scope в CI выполняется до кода PR, валидатор и карточка берутся из одного
   точного base SHA. Валидатор запускается из временной папки с `-I`, чтобы код
   PR и PYTHONPATH не подменяли его импорты. Bootstrap остаётся только для H0;
   при наличии политики и отсутствии скрипта в базе проверка завершается ошибкой.
2. Чтение/запись JSON, Markdown, Python, snapshot и CODEOWNERS используют UTF-8
   явно. Исправлены также фикстуры и декодирование вывода `git config`.
3. Hooks и validate.sh используют общий `.githooks/run-python.sh`: сначала
   окружение проекта, затем рабочие python3/python/py -3. Аргументы и stdin
   pre-push сохраняются; при отсутствии Python выводится понятная ошибка.
4. Добавлены 10 регрессионных тестов и job windows-harness на Python 3.12
   с PYTHONUTF8=0 и ошибкой при неявной кодировке. Документация обновлена.

### Фактические проверки

Windows, CPython 3.12.14, locale CP1251. Проверка выполнена через Python из
локального .venv, без активации и без глобального alias python3. Для вывода
кириллицы в консоль использовано PYTHONIOENCODING=utf-8; кодировка файлов
при этом не меняется. Установлены PYTHONUTF8=0, PYTHONWARNDEFAULTENCODING=1
и PYTHONWARNINGS=error::EncodingWarning.

не выполнялись. Ветку A0 и рабочую папку первоначального review не меняли.
Полные GitHub Actions для исправленной версии и Linux-runner ещё не запускались;
shell-сценарии локально проверены через Git for Windows. Backend/frontend в этой
версии H0 отсутствуют и явно неприменимы; Syncthing, Docker и VPS не запускались.

Следующий шаг: danilsdk проверяет патч, применяет его к указанному head H0,
повторяет validate в своей ветке и публикует изменения. После успешного CI
проводится повторная проверка нового head; обсуждения не закрываются авансом.
