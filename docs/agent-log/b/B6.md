## Получившееся поведение

GitHub Actions запускает штатные проверки harness, backend и frontend на
Linux amd64, Windows amd64 и macOS ARM64 с Python 3.12 и Node.js 24. Ещё одна
задача на macOS ARM64 проверяет частные PostgreSQL и два Syncthing. Каждая
платформа сообщает фактические версии и архитектуру, а нативная интеграция
добавляет коды завершения, результаты SQL/API и итог очистки.

## Решения и изменения

- Check `validate` сохраняет имя и требует успешного завершения матрицы и
  отдельной нативной интеграции. Матрица завершает проверки на каждой платформе
  даже после ошибки одной из них.
- В PR исполняется принятый harness из base SHA. Scope читает политику этого
  SHA и сохраняет исключение для первоначального H0. Остальные шаги работают
  с проверяемым деревом PR и токеном с разрешением `contents: read`.
- `scripts/check_platform.py native` запускает принятые сценарии A10/A3
  последовательно. SQL-наборы проверяются по свежему JUnit, API и Syncthing —
  по своим отчётам. Подробные материалы хранятся в приватном runtime. При
  таймауте helper даёт своей группе процессов время на штатную очистку.
- Python читает backend текущего checkout. Для нативной интеграции используется
  Homebrew PostgreSQL 17 с отдельным временным кластером на каждый этап.

## Ограничения и продолжение

После публикации B6 сверить результаты всех четырёх проверок и итоговый
`validate` на одном head. Для воспроизведения использовать
[инструкцию матрицы](../../harness.md#матрица-платформ). GitHub `macos-26`
оставляет patch-версию за образом раннера. Контейнерный ARM64-прогон относится
к A4.
