## Получившееся поведение

Добавлен bounded reconciliation pass и A4-инъектируемый `ReconciliationRuntime`.
Один worker читает активные правила и pending intents, пересчитывает desired state
через B1 на текущий момент, получает свежую конфигурацию через `AdapterFactory`,
фиксирует pending и `sent_at` отдельными commit до внешней команды, вызывает только
адаптер и выполняет повторное чтение системы/папки/restart flag.

HTTP/write-успех без свежего наблюдения остаётся `unknown`; mismatch даёт `failed`,
смена source session, timeout, restart и потеря наблюдения не дают ложного `applied`.
После worker restart уже отправленная pending-команда становится `unknown`, а
неотправленное намерение отменяется для нового расчёта. Manual resume создаёт
идемпотентный pending intent, запрещён при активном правиле и читается через
историю.

Добавлен защищённый API `/api/executions`: пагинация/фильтры истории, чтение одной
попытки и `POST /resume` с повтором idempotency key (`202`/`200`). Роутер не запускает
worker и использует общую auth/session/lock сборку A0.

### Продолжение 2026-10-29

После обновления B1 ветка B2 получила его исправление частичного PATCH обычным
merge `ca57f82`. В reconciliation найдено расхождение с D-04: после отправки
правила внешний ответ и совпавшее состояние могли быть записаны как `applied`,
даже если правило изменилось во время вызова. `_finish` теперь повторно читает
версию и enabled под advisory lock; при удалении, отключении или смене версии
старая попытка становится `unknown` с `rule_changed_after_send`, после чего
следующий проход рассчитывает новое правило. Ошибка разрешения адаптера теперь
не останавливает worker: для rule-pass она оставляет недоступное наблюдение до
следующей попытки, для ручного intent фиксируется как `unknown` с безопасным
кодом адаптера. Добавлен unit-тест финальной сериализации подтверждения.
