## Получившееся поведение

Подготовлен [план коллектора](../../design/a/collection.md), реализован EventCollector:
одна попытка чтения и атомарной записи событий/маркеров/checkpoint, без scheduler

## Решения

- События, bounded HistoryGap, границы эпох и полный checkpoint/cursor пишутся
  одной транзакцией под блокировкой строки узла и сверкой исходного снимка.
  При пустом пакете другой эпохи переход откладывается; старый cursor в новую
  эпоху не переносится. Между недоказанными эпохами диапазоны не выдумываются.
- В каждой сетевой попытке — своя фабрика/клиент; после rollback/CAS/неизвестного
  commit внутреннее состояние адаптера не используется как каноническое.
- Отдельная явная system-проверка даёт одну node-запись; config/runtime папки
  сохраняются раздельно. Ошибка потока не превращается в ложную недоступность.
  Отсутствие пробы не добавляет фиктивных неуспешных измерений.
- История читается только из БД, фильтруется по received_at/observed_at в [from,to),
  сортируется по времени,id DESC; существующие DTO и девять маршрутов A2 неизменны.
- A3 предоставляет service/router; A4 подключает в один worker с B2 и общую
  сборку API. Новая схема/расширение allow/второй singleton-процесс не планируются.

### Реализация

- Pure planner повторно валидирует EventBatch и вложенные поля, проверяет UUID,
  эпоху/raw time/anchor, возрастающие bigint ID и безопасные имена/payload.
  Пустой пакет той же эпохи обновляет доказательство без продвижения cursor;
  пустой пакет другой эпохи откладывает переход без переноса старого cursor.
- Source, bounded HistoryGap, SourceRestarted/SourceContinuityLost и canonical
  поля ManagedNode сохраняются одной PG-транзакцией под FOR UPDATE и полным CAS
  checkpoint/cursor/identity/alias/серверного target. Source unique conflict
  не переписывает существующую строку. Между эпохами диапазон не выдумывается.
- Папки разрешаются только внутри node_id, в том числе present=false; неизвестный
  внешний ID даёт folder_id=null без создания папок из event data. Сырой payload,
  пути и globalID не становятся данными курсора/истории.
- EventCollector использует свежую фабрику A1/NodeResolver A2 на каждую попытку,
  read_events(..., timeout_seconds=0), одну ограниченную rebase-попытку и close
  в finally. Доступ к сети не удерживает SQL lease. Старое состояние клиента
  после rollback/неизвестного commit не используется повторно.
- CollectionResult возвращает stored/conflict/deferred/skipped/error и безопасный
  код. Неизвестный commit перечитывается из БД, ошибка close после успешного commit
  не стирает подтверждённые счётчики/cursor. Snapshots/api_status/paused не меняются.
- Код находится только в collection и собственных тестах. Общие DTO/модели,
  миграции, main/config, адаптер и зоны B не менялись; новых зависимостей нет.

## A3.3 — наблюдения

2026-10-26. Поручение охватывает A3.3–A3.5 с подготовкой A3 к review.
База e5eb0b5d56412f045f6ddb9dac1fa52666904685, снимок
a3-observations/A33-start.json вне Git; исходное состояние чистое.

Реализованы ObservationCollector и CollectionService. Одна явная проверка узла
создаёт один scope=node snapshot; config и runtime папок — отдельные записи.
Ошибки runtime не стирают успешный config/старый кеш. Успешный полный список
обновляет present; при ошибке списка исчезновение не выдумывается. Проверка
эпохи после чтений запрещает смешанные folder-наблюдения. Неожиданное исключение
подфазы даёт безопасный internal_error, сохраняя уже выполненную system-проверку.

Сеть выполняется без SQL lease, запись снимков и кеша — отдельной транзакцией
после event-фазы. Поздние измерения остаются в истории, но не затирают новый кеш.
При concurrent disable сохраняется история без применения кеша; при смене
identity/серверного target пакет отклоняется. Canonical checkpoint не меняется.
Последовательный collect_once использует последнее node-наблюдение мониторинга
для интервала 30 секунд, поэтому чтения реестра не задерживают сбор и пропущенные
тики не создают фиктивные проверки. Запуска scheduler/worker в API нет.

Проверки: **26 unit коллектора** (21 прежний + 5 новых) и **63 на частной PG**
(41 прежний + 22 новых), без warnings. Ruff/format прошли. PostgreSQL upgrade/check
выполнены; два собственных кластера остановлены и удалены. Реальные Syncthing
пока не запускались; итоговый общий набор и полный стенд выполняются в A3.5.
Отчёт SQL: a3-observations/postgres.xml вне Git. Общая схема/DTO/main/config
и ветки A0/A1/A2 не менялись; карточка A3 не расширялась.
