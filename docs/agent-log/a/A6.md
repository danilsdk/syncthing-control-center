отправку. R2: общая API-зависимость переводит ожидаемые ошибки resolver в
безопасные 404/503. R3: SourceEvent ограничивает id диапазоном bigint и не
выпускает ошибку нормализации за AdapterError. R4: настройки имени используют
тот же DisplayName, что публичный DTO.

карточка с точными путями; allow A1/D01 не расширяется. Схема и миграции,

## Реализация

- R1: общий RLock согласует проверку closed после connect, публикацию сокета
  и начало отправки с close. Watchdog сохраняет возможность shutdown/close;
  ожидание ответа выполняется вне блокировки отправки. Если владелец закрыл
  транспорт до начала отправки после connect, PATCH получает not_applied.
  Для уже начатой отправки unknown остаётся допустимым консервативным исходом.
- R2: только разрешение узла в get_adapter переводит not_found в AppError
  404/not_found, остальные AdapterError — в 503/service_unavailable. Сообщения
  фиксированы; обработка метода и write_outcome остаётся у владеющего сервиса.
- R3: SourceEvent.id ограничен 2**63-1, как StreamAnchor. Некорректное значение
  отсекается в _events как invalid_response до изменения checkpoint.
- R4: ConnectionSettings использует общий DisplayName. Проверено отклонение
  пробелов/переводов строк и сохранение допустимого имени в публичном DTO.
