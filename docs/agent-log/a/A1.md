## Выполнение A1.1

Поручение пользователя: «тогда переходим к A1.1». Создан воспроизводимый
[стенд](../../../deploy/syncthing/README.md) из двух переносимых процессов
на Windows amd64. Архив из `release.json` проверяется по зафиксированному
SHA-256 до извлечения и каждого запуска. Реальный бинарник и API — v2.1.7.
Две первоначальные загрузки превысили бюджет 90 секунд; увеличен бюджет до
300 секунд, добавлено чтение блоками 64 KiB с прогрессом. Итоговый архив
скачан, SHA-256 совпал; непроверенный бинарник не запускался.

В `deploy/syncthing/` добавлены prepare/capture/bench, точный релиз и инструкция.
У каждого узла отдельный помеченный home, собственные ключи, Device ID,
две демонстрационные папки и loopback-порты. Изоляция подтверждается чтением
реальных options. Конфигурация задаётся офлайн только в собственных XML.
Существующий непомеченный home или занятый порт останавливает подготовку.
Остановка сверяет PID, время создания процесса и путь бинарника; чужие
экземпляры не останавливаются. API-клиент стенда запрещает PATCH и redirects.
Ключи, сертификаты, бинарники и журналы остаются в игнорируемом runtime.


Два полных запуска verify завершились успешно; последний —

discovery/relay/NAT отключены, listeners привязаны к loopback,

сами байты, SHA-256 записан в

Оба процесса остановлены в finally, status показывает `running=[]`.
Это чтения, запись временного файла и POST db/scan; paused PATCH не выполнялся.

Сохранены 18 сокращённых реальных ответов + manifest в
`tests/contract/syncthing_adapter/fixtures/v2.1.7/`: по семь успешных GET,
403 для неверного ключа и 404 для отсутствующей папки на каждый узел.

проверяются до записи любого fixture.

### Ограничение, выявленное исследованием API

Реальный startTime имеет точность до секунды. В официальном коде v2.1.7
[StartTime обрезается до секунды](https://github.com/syncthing/syncthing/blob/v2.1.7/lib/ur/usage_report.go),
а [system/status возвращает это значение](https://github.com/syncthing/syncthing/blob/v2.1.7/lib/api/api.go).
Следствие: текущий helper A0 из UUID узла и raw startTime может повторить
source_session_id для двух запусков в одну секунду. Такой быстрый рестарт
отдельно не воспроизводился; ограничение следует из кода источника.
Смена сессии по одному startTime не считается надёжно доказанной.
Вопрос зафиксирован для review A0 и решения перед A1.3. Общий контракт
в рамках этого подэтапа не изменён; агент не публиковал сообщение напарнику.

### Границы доказательств

Стенд и его чтения проверены на Windows, путь Linux только подготовлен.
Pause/resume, сохранность полей при PATCH и issue #10389 остаются для A1.4;
long polling, restart detection и события адаптера — для A1.3.
Полный harness validate отсутствует в ветке A0/A1: его код не объединялся
до приёмки H0. Вместо заявления об успешном validate выполнен read-only
scope исправленным helper H0 по принятой для работы карточке:

```text
python ../.h0-fixes/scripts/harness.py scope --task A1 --base 15088e2c12088a9987944367a3bf358fdf4f06a4 --policy-ref 00c2bf63cd628e764af7f1c237514808eed5b576
```

Scope подтвердил все 30 файлов в границах A1; git diff --cached --check прошёл.
Проверены 14 локальных ссылок, отсутствие обоих реальных API-ключей в доступных
Git файлах, игнорирование runtime и отсутствие слушателей на четырёх портах.
Готовые
PR напарника сверены: H0 #1 остаётся на прежнем head `00c2bf6`, замечания
предыдущего review ещё относятся к этому коду; A0/H0 не считаются принятыми.
