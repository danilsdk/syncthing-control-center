Две первоначальные загрузки превысили бюджет 90 секунд; увеличен бюджет до

### Ограничение, выявленное исследованием API

Реальный startTime имеет точность до секунды. В официальном коде v2.1.7
[StartTime обрезается до секунды](https://github.com/syncthing/syncthing/blob/v2.1.7/lib/ur/usage_report.go),
а [system/status возвращает это значение](https://github.com/syncthing/syncthing/blob/v2.1.7/lib/api/api.go).
Следствие: текущий helper A0 из UUID узла и raw startTime может повторить
source_session_id для двух запусков в одну секунду. Такой быстрый рестарт
отдельно не воспроизводился; ограничение следует из кода источника.
Смена сессии по одному startTime не считается надёжно доказанной.
Вопрос зафиксирован для review A0 и решения перед A1.3. Общий контракт
в рамках этого подэтапа не изменён; агент не публиковал сообщение напарнику.

### A1.2 — чтения и фабрика

Добавлены HttpSyncthingAdapter, HttpAdapterFactory и ResolvedNode. Resolver
принимает внутренний UUID и возвращает серверное подключение с ожидаемым
Device ID. При первичном обнаружении допустим None, затем клиент закрепляет
первую корректную идентичность. При смене ключа/адреса/ID фабрика закрывает
старый клиент; ошибка resolver также запрещает его дальнейшее использование.
Фабрика реализует for_node/close A0. Реестр и сборка приложения не менялись.

Транспорт — стандартная библиотека Python; общие зависимости не менялись.
Запрещены redirects, proxy environment и скрытые повторы. TLS проверяет
сертификат/hostname. HTTP/socket timeout 5 секунд, события server 0–15 и HTTP
server+5; watchdog прерывает медленные заголовки/тело. Системное DNS-разрешение
имён не получило отдельного отменяемого resolver. Размер тела — до 4 MiB.
JSON требует UTF-8 и не принимает duplicate keys/NaN/Infinity. Ошибки безопасны,
upstream-тела и ключи не выдаются. 401/403/404 классифицируются без разбора JSON.

Чтения проверяют identity, сохраняют исходные времена, неизвестные непустые
state и None для отсутствующих счётчиков. Пустой label отображается как Folder
ID, длинный ограничен 80 символами по DisplayName A0. ID папки кодируется
одним сегментом пути/query-параметром; типы не приводятся из строк.

### A1.3 — события по текущему D-01

Реализованы фиксированный поток без смены фильтра, ограниченный long poll,
пустой пакет, строгие возрастающие id, отдельный globalID, исходное время
с долями секунды и безопасный payload. Полные данные событий отбрасываются;
в state остаётся только разрешённая строка StateChanged.to, без путей/ошибок.

Статус читается до/после получения пакета. Смена сессии/идентичности запрещает
приём всего пакета. Последняя позиция того же потока дополнительно проверяется
через since=0/limit=1/timeout=0. Регресс уже виденной позиции, другая исходная
отметка для того же id или уменьшившийся uptime при прежнем startTime
карантинируют сессию до нового startTime. Старый курсор выше текущего конца
отклоняется; обычный новый startTime позволяет начать с since=0.

Решение в границах A1: сохранить helper и семантику draft D-01, не менять
общие файлы A0. Эти дополнительные проверки не делают startTime уникальным:
незамеченный restart в ту же секунду с уже обогнавшим старый курсор потоком
может остаться неразличим. Полная приёмка A1.3 требует решения A0/B0;
не заявляется обнаружение любого возможного рестарта.

Локальный отказ до отправки и 401/403/404 — not_applied; timeout, обрыв после
начала отправки, 5xx, неверная ответная идентичность — unknown.
Подтверждающие чтения выполняются отдельно, окончательная политика — B2.

(2026-10-25 по Москве). Сохранён
[обезличенный отчёт](../../../tests/integration/syncthing_adapter/evidence-adapter-v2.1.7.json):

### Отказы первого прогона и исправления

Первый реальный прогон обнаружил ошибку транспорта при Connection: close:
после полного тела нельзя снова менять timeout уже закрытого сокета.
Исправлено условие окончания чтения, добавлен отдельный настоящий HTTP-тест.
Повторный запуск выявил ошибку стенда A1.1 после сохранения XML: первый device
может оказаться peer, поэтому Device ID теперь читается из сертификата через
CLI device-id. Добавлена регрессия на отсортированный XML. При всех неудачных
прогонах собственные процессы были остановлены. Непустой обязательный runtime
DTO не расширялся молча ради paused-ответа; сценарий разделил наблюдения.
