## Решения

По поручению «давай перейдем к A1. определим что нужно сделать» создана отдельная
ветка поверх текущего A0. A0 в PR #2 ещё ожидает review danilsdk; контракт
0.1.0-draft не считается принятым. H0 (#1) и его исправления (#3) также открыты.
Их код не смешивается с A1.

Подготовлен [план A1 и проверка API](../../design/a/syncthing-api.md):

1. A1.1 — версия, изолированный стенд и реальные обезличенные ответы.
2. A1.2 — чтение состояния, фабрика и безопасные ошибки.
3. A1.3 — события, точная сессия источника и проверка её смены.
4. A1.4 — paused без изменения соседних полей и подтверждающие наблюдения.
5. A1.5 — общий набор проверок и передача A2/A3/B2.

Выбран официальный стабильный Syncthing 2.1.7 от 21 октября; метаданные архивов
и SHA-256 проверены по GitHub Releases API. Сами архивы ещё не скачивались.
Docker CLI и Docker Desktop в стандартном месте не найдены; первый стенд
запланирован как два переносимых процесса Windows с отдельными данными и портами.
Выбор не требует менять общие контракты или dependency-файлы A0.

Прочитаны протоколы/DTO A0.4, раздел 7 общего контракта, карточка и профильные
инструкции из H0. Сверены официальные страницы Syncthing config/status/events/
db-status/CLI и исторический issue #10389 о побочном изменении настроек при PATCH.
Применимость этого дефекта к выбранной версии не заявляется.

`b4e8061b3e632eed13584b50797bb6ee5a44a4a2`: чужих untracked-файлов — 0.
Так как правила игнорирования H0 ещё отсутствуют в A0, снимок временно сохранён

Helper использовался для локального снимка, а не как доказательство приёмки H0.

Подготовлены только два документа в разрешённых путях A1. Код приложения,
адаптер, зависимости и чужие ветки не менялись. Новые продуктовые тесты
на этапе планирования не требуются. Реальные Syncthing, изменение paused,
таймауты HTTP, синхронизация файлов и restart ещё не проверялись.

Проверка scope по зафиксированной карточке H0 прошла: оба новых документа
в границах A1. Проверены четыре локальные Markdown-ссылки; git diff --check

harness и тесты ещё не реализованного адаптера успешными не объявляются.
