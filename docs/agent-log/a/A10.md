# A10: нативная совместимость macOS ARM64

- ID / роль / исполнитель: A10 / A / playerboom.
- Статус: реализация подготовлена к независимому review; до приёмки на Mac не принята.
- Ветка: `codex/a10-macos-compatibility`, отдельный worktree `syncthing-control-center-a10`.
- База: принятый `main` / `76062626716bbd9aab883d53598b3a2577b08d08`, план из PR #18.
- Требования: F-10; переносимость нативного стенда, защитные регрессии и T-02–T-04.
- Commit / PR: журнал записан перед публикацией; точные head/base, ссылка и CI
  фиксируются в описании PR ветки `codex/a10-macos-compatibility`.

## Получившееся поведение

Для macOS ARM64 подготовлены официальный ZIP Syncthing 2.1.7, отдельные формат
архива и имя бинарника. Intel/Rosetta не принимаются за нативный ARM64.
Darwin использует libproc для PID/времени создания/пути исполняемого файла;
Linux `/proc`/pidfd и Windows handles сохранены для своих платформ.
Неуспешный shutdown Mac сохраняет runtime и не переходит к сигналу по PID.

## Решения и изменения

- Python 3.12, Syncthing 2.1.7 и зависимости backend не изменены. API, модели,
  worker, Compose и CI остаются в прежних карточках.
- Mac digest сверён с GitHub release metadata и официальным sha256sum.txt.asc:
  `2df075b463231a307c91da657157beaed06383a941ba7ea04d33d536e3c4af38`.
  Архив скачан и проверен на Windows; извлечён Mach-O 64-bit ARM64,
  35 747 424 bytes. Это доказательство архива, а не запуска на Mac.
- При проверке настоящего ZIP обнаружены одноимённые service/firewall-файлы
  `etc/*/syncthing`. Выбор по одному basename отвергал релиз как неоднозначный.
  Выбор ограничен корнем release; вложенные скрипты не извлекаются. Это также
  сохраняет tar.gz-путь Linux, где присутствуют такие же служебные файлы.
- Darwin ABI основан на Apple proc_info.h/libproc, Rosetta probe — на
  sysctl.proc_translated из документации Apple. Время начала читается по обе
  стороны proc_pidpath; неполные/недоступные наблюдения не считаются остановкой.
- Ошибка наблюдения сразу после spawn сохраняет `pending_pid`; status/stop
  возвращают ошибку, не объявляя неизвестный процесс остановленным. Путь
  `ENOENT` также не считается исчезнувшим PID: kernel может вернуть его из
  vnode lookup для живого процесса; отсутствие подтверждается только ESRCH.
- Исправлен запуск трёх прежних platform regressions: Mac может выбрать свой
  архив и проверить реальный PID вместо отсутствующего /proc.
- D-01 больше не перезаписывает tracked evidence при обычном запуске;
  для этого предусмотрен явный `--export-evidence`.
- Полная инструкция чистого окружения и последовательной приёмки находится
  в `docs/design/a/macos-development.md`.

Native D-01/A2/A3 повторно прошли после добавления защиты pending PID.
Последующее уточнение ENOENT и две его регрессии относятся только к Darwin;
Windows ветка процесса после native-прогонов не менялась. Финальные 61 contract
прошли. Обязательный полный pre-push и GitHub validate проверят публикуемый head;
их точные результаты и SHA приведены в PR, без выдачи старого CI за новый.
209 SQL-проверок выше выполнены отдельно от 99 штатных skips общего validate.
Свои API, singleton worker, два Syncthing и временные PG-кластеры завершены;
частные кластеры удалены, исходные четыре demo-конфигурации восстановлены.
Принадлежащие стенду home, кеш и приватные отчёты остаются в игнорируемом runtime.
Обезличенная сводка с проверкой отсутствия ключей и личных путей сохранена в
`tests/integration/syncthing_adapter/evidence-a10-windows-2026-11-18.json`.
Она содержит SHA-256 рассматриваемых исходников, отличает окончательные contract
от предыдущего полного validate и не заявляет нативного выполнения на Mac/Linux.
Хеши Git blob с нормализованным LF и реальные байты Windows checkout записаны
раздельно: CRLF checkout не должен давать ложное расхождение на Mac/Linux.

Локальный Ubuntu 20.04 доступен только с системным Python старой версии;
проект под Python 3.8 не запускался. Linux-результаты берутся из обязательного
GitHub CI на Python 3.12. Живой Linux-прогон этой реализацией не заявлен.

Первая загрузка Windows-архива завершилась URLError при стандартном CA-наборе
окружения; повтор с уже установленным доверенным Git CA bundle прошёл.
TLS и SHA-256 не отключались. Дополнительная проверка Ruff сначала запускалась
без проектного config и включила чужие правила линтера; с явным config проекта
она прошла, без форматирования всего репозитория.

Первая попытка push остановилась на 32 self-test errors harness: Git передаёт
hook переменные GIT_DIR/GIT_WORK_TREE, а тесты создают иностранные репозитории
без очистки этого окружения. `git init/config` попали в исходный репозиторий:
появились тестовая user identity и core.bare=true; до commit тестовых данных
исполнение не дошло. Ветки, исходники и remote проверены и сохранены, локальные
user.name/email восстановлены из собственного commit до сбоя, core.bare=false
восстановлен по исходному рабочему main. Глобальная конфигурация не менялась.

Для публикации используется временный локальный wrapper вне Git: очищает
`git rev-parse --local-env-vars`, затем из этой рабочей папки исполняет
неизменённый `.githooks/pre-push` со всеми проверками. Это соответствует
[рекомендации Git для foreign repository из hook](https://git-scm.com/docs/githooks).
Путь задан только для одной команды push; исходный repo hooksPath остаётся
`.githooks`. CI дополнительно проверяет опубликованный head по принятому harness.
Исправление самого harness не включено в A10; нужен отдельный H0-разбор B.

## Review и вклад человека

Независимое review и реальный Mac-прогон danilsdk ожидаются. Изменение своей
demo-конфигурации и её восстановление человек подтверждает до merge на точном SHA.
Самостоятельный approval/merge этой ветки не выполняется.

## Ограничения и продолжение

Mac runtime, native libproc, полный validate и живой A3 на Mac нельзя объявить
проверенными по doubles или Windows. После передачи PR B выполняет инструкцию,
фиксирует версии/архитектуру/head/base и результаты, затем проводит review.
До этого A10 не принята. После приёмки A10 — B6, полная ARM64 Compose-приёмка — A4.
