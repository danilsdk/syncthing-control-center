## Решения

- A4.2 — core PG/API/2 Syncthing с одноразовой миграцией и явным admin-create;
  можно выполнять до B1–B3, не выдавая за полный MVP.

  A4.4 — UI B3/одна origin и CI; A4.5 — реальный system/E2E и review.
- Один image API/worker, Python 3.12, PG 18, Syncthing v2.1.7; конкретные
  registry tags/digests проверяются в A4.2. В A4.1 контейнерные версии не проверены.
- PG/Syncthing REST внутри закрытого стенда; host-порты только loopback для API/UI.
  Собственные volumes/project, без копирования ключей и home из нативного стенда.
- File secrets и bounded deploy entrypoint; не предполагать, что Settings уже
  поддерживает *_FILE. Реальный администратор создаётся вручную, без startup seed.
- Существующий run_worker/WorkerContext используется с singleton. Блокирующий
  run B2 не обеспечивает общий цикл A3 сам по себе; конечный шаг/hook согласовать
  с B2 до A4.3, не добавлять второй worker или API scheduler.
- Приёмка/база H0/A0/A1/A2/A3, D-01/B0 и поставка B1/B2/B3 ожидаются; полного
  harness validate в текущей базе нет. VPS — отдельное поручение.

### Первоначальная блокировка среды, снята ниже

Docker сообщил создание VHDX: virtual disk support provider not found. Эта же
ошибка подтверждена отдельным встроенным DiskPart с новым собственным динамическим
VHDX максимум 32 МБ; образ не подключался, probe-файл/команды удалены. Службы
vmcompute и vds были остановлены; после стандартного UAC запущены. Повторный
старт Desktop сохранил ошибку. Найден отключённый Microsoft Virtual Drive Enumerator,
ROOT\VDRVROOT\0000, Code 22. Команда Enable-PnpDevice через UAC выполнена, но
фактический Code 22 и отказ создания VHDX сохранились. ConfigFlags уже 0;
успешное восстановление не заявляется. WSL/VMP включены, hypervisorlaunchtype Auto;
Windows сообщает HypervisorPresent=false и firmware virtualization=false.

Рабочие WSL Ubuntu/данные не удалялись, factory reset, registry/boot изменения,
переустановка или восстановление Windows не выполнялись. Эти диагностика/скрипты
хранятся вне Git в a4-core. Следующий шаг — полная перезагрузка Windows и повторная
проверка устройства/VHDX/виртуализации; затем реальный build и check_core.py.
До успешных контейнерных проверок **A4.2 не завершён и не готов к приёмке**.
