# Задания агентам двух участников

Ты — B / danilsdk (автоматизация и интерфейс), друг — A / playerboom (интеграция и данные). Пакеты ниже относятся к этим ролям. Они описывают будущую работу:
сейчас ни одна карточка не отмечена выполненной. Одна карточка — один владелец,
но крупный пакет можно сдавать несколькими небольшими PR.

Перед задачей используйте `python3 scripts/harness.py prompt ID` и `$scc-task`.
Точные пути в `.harness/tasks/ID.json` имеют приоритет над кратким перечнем ниже.
Собственный журнал и JSON-карточка входят в область задачи; расширение границ
не выполняется попутно. Текст ниже объясняет предметный результат.
Если несколько агентов работают одновременно, уточняйте непересекающиеся пути
внутри этой границы и давайте каждому отдельный worktree.

**Готово, когда:** каркас запускается, миграция применяется к пустой тестовой БД;

## Как передать карточку агенту

Подготовьте отдельный worktree командой `start ID` после публикации harness.
Передайте выведенный запрос агенту в новой рабочей папке. Для текущего worktree
используйте `prompt ID`; полный процесс — [harness](harness.md).

Готовые первые задания:

- [Твоему агенту — B0 / danilsdk](prompts/start-b.md).
- [Агенту друга — A0 / playerboom](prompts/start-a.md).

Публикация поручена в этих стартовых запросах: агент делает commit, push своей
ветки и PR, агент напарника проверяет и при готовности объединяет результат
по постоянному поручению AGENTS.md. Локальный вызов `prompt` сам по
себе не добавляет разрешение push, если участник ещё не поручил публикацию.

Для отдельно назначенного reviewer используйте `$scc-review` и ID карточки.
Попросите читать полный diff и журнал без изменения кода. Журнал каждой задачи
оформляется по [шаблону результата](templates/agent-result.md).
