# Review-заметки к A0 из B0

Проверенная версия: PR #2, head

## Найденные блокирующие вопросы

1. **Граница карточки A0 нарушена.** Diff PR содержит
   `.harness/tasks/A9.json` и `docs/agent-log/a/A9.md`, хотя
   `.harness/tasks/A0.json` разрешает только карточку A0 и её журнал. После
   принятия H0 `review-plan` должен отвергнуть такие пути. Уберите эти два файла
   из A0 либо вынесите их в отдельную карточку/PR, не расширяя `allow` A0.
2. **Контракт остаётся draft до согласования B0.** Реализацию B1 следует строить
   по D-03/D-04/D-05: `[start,end)`, окно через полночь по дню начала,
   `desired_paused=null` для выключенного правила, `unknown` для недостаточного
   наблюдения и `null` при нулевом знаменателе. Эти решения должны попасть в
   принятую версию контракта без изменения семантики в роутере.
3. **Проверка платформы должна быть явной.** A0 требует Python 3.12 и `tzdata`,
   что подходит Windows и macOS при установке зависимостей. В дальнейшем CI и
   runbook должны выполнить хотя бы bootstrap/contract suite на Windows и macOS
   либо явно отметить, что Docker Desktop является обязательным локальным
   способом запуска PostgreSQL/Syncthing. Не использовать POSIX-пути в коде.

## Что B0 подтверждает

- Поля `RuleCreate`/`RulePatch` и IANA timezone достаточны для согласованного
  вычисления; B1 не требует новой миграции.
- `ExecutionStatus`, snapshot версии, `sent_at` до HTTP и отдельная проверка
  `restart_required` позволяют не считать HTTP 200 подтверждением.
- `Snapshot(scope=node)` с `success/error_code` позволяет считать доступность
  без умножения знаменателя на число папок, если A3 сохранит одну запись на
  проверку узла.

До approval ожидается исправление границ PR и повторная проверка актуального
head/base после принятия H0.
