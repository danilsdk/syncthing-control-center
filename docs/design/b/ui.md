# Веб-интерфейс B3

Реализован React/TypeScript/Vite-клиент принятых API A2/A3/B1/B2.
Интерфейс готовится к независимому review; полный стенд Syncthing остаётся A4/B4.

## Запуск и сборка

Нужен Node.js 22.12+ (ветка 22), 24 или 26+, npm 10+ и Python 3.12 для backend.
Из каталога `frontend`: `npm ci`, затем `npm run dev`. Vite слушает localhost:5173,
проксирует `/api` и `/health` на `http://127.0.0.1:8000`. `B3_API_TARGET` меняет
только серверный адрес proxy; в браузер он не передаётся. API всегда same-origin.
Для входа backend должен разрешать точный Origin интерфейса:
`SCC_ALLOWED_ORIGINS=["http://localhost:5173"]` (JSON-строка переменной окружения).
Администратор создаётся серверной командой из инструкции A2, не через frontend.

`npm run build` создаёт `frontend/dist`. A4 должен отдавать этот каталог и `/api`
под одним HTTPS origin, настроить server-only `SCC_SESSION_SECRET`, подключения
Syncthing и разрешённый origin. Токен CSRF живёт только в памяти вкладки;
HttpOnly cookie обслуживает backend. После перезагрузки вкладки `/api/auth/me`
восстанавливает CSRF и сессию. Выход считается завершённым после ответа сервера.
При 401 из чтения или изменения workspace размонтируется вместе с данными.

Для демонстрации есть отдельная команда `npm run dev:mock` и безопасный
`frontend/.env.demo`. Она использует fixtures одного экземпляра MockProvider,
показывает постоянный баннер и не проверяет пароль. Обычные dev/build используют
API; ошибка сети никогда не переключает клиент на mock. Времена demo актуальны
на момент создания провайдера; неизвестное наблюдение остаётся неизвестным.

## Экраны и состояния

Навигация — hash-маршруты `/#/overview`, `/#/folders`, `/#/rules`, `/#/history`,
`/#/analytics`. Для статического хостинга не требуется backend SPA-router.

| Экран | Поведение |
| --- | --- |
| Вход | Проверка существующей сессии, логин/пароль, понятные ошибки, срок сессии |
| Обзор | Узлы, свежая доступность, число папок и правил, последняя попытка |
| Папки | Фактическая пауза, режим по расписанию, runtime и времена наблюдений, фильтр узла |
| Правила | Создание, редактирование, включение/отключение, удаление с подтверждением |
| История | Команды с UTC-периодом `[from,to)` и статусом. События Syncthing с фильтром по узлу и папке. Серверная пагинация |
| Аналитика | Заготовка клиента контракта B4; null отображается как «Нет данных» |

Ресурсы загружаются независимо: отсутствие аналитики не блокирует правила.
Ошибки чтения отличаются от пустой коллекции. При частичном отказе папок
сохраняются доступные карточки и показывается ошибка конкретного узла.
Узел с `api_status=ok`, но `is_stale=true`, не считается доступным в сводке.
Неизвестные/устаревшие конфигурации не получают зелёного статуса. Runtime показан
со своим временем и не выдаётся за свежий только по свежести конфигурации.
Данные workspace перечитываются каждые 30 секунд и кнопкой «Обновить».

Ручное возобновление доступно для присутствующей папки enabled-узла, после свежего
наблюдения паузы и загрузки правил, без активного правила. Учитывается и
`active_rule_id`, даже если правило не найдено в клиентском списке. При потере
ответа POST клиент сохраняет ключ идемпотентности для повтора в текущей вкладке.
Получив ID попытки из POST, клиент освобождает ключ, чтобы у следующей команды
был свой. Пока открыт экран «Папки», клиент опрашивает отдельный GET попытки
каждые 1,5 секунды и показывает итоговый статус из этого GET. При ошибке GET
доступно перечитывание.
История команд перечитывается раз в 3 секунды, пока на странице есть pending.
Журнал событий использует `GET /api/events` и показывает события источника,
пропуски, перезапуск Syncthing и утрату непрерывности. Для `ItemFinished` доступен
факт завершения обработки. A3 передаёт тип, папку и время, а для показа имени
файла и исхода обработки требуется расширение контракта.

Каждая PATCH/DELETE передаёт `expected_version`; конфликт 409 требует нового
чтения, автоматического повтора старого изменения нет. В форме проверяются
непустые дни, отличающиеся границы окна и IANA timezone. Рядом с полями объяснены
разрешённое время синхронизации и переход через полночь. Отключение расписания
прекращает управление по времени. После сохранения показаны последнее свежее
наблюдение или неизвестное состояние и ссылка на экран «Папки», где доступно
ручное возобновление при свежем наблюдении паузы.
Все времена наблюдений/истории отображаются явно в UTC, время расписания — в IANA.

## Визуальные решения

Основной источник — существующий B3: тёмная консоль, левая навигация, компактные
панели, акцент бирюзового цвета. Сохранены её структура и плотность. Исследование
выполнено по bundled references навыка Refero; live Refero MCP недоступен.

| Решение | Источник | Назначение |
| --- | --- | --- |
| Системный шрифт, без сетевых fonts | Refero `references/typography.md` | Предсказуемый рендер русскоязычной панели без внешних запросов |
| Тёмные поверхности и один акцент | Существующий B3 + Refero `references/color.md` | Акцент для действий/навигации, amber для неопределённости, red для ошибок |
| Видимый focus, подписи, native dialog | Refero `references/craft-details.md` | Клавиатура, отмена Escape, сохранение фокуса и блокировка фона |
| Пауза и цель рядом, отдельные времена | Контракт и frontend/AGENTS.md | Различать наблюдение и намерение, не скрывать неизвестное |
| Таблица прокручивается внутри панели | Ограничение 360 px + craft-details | Страница не выходит за экран; навигация и выход доступны |

Направление зафиксировано до изменений; новых bitmap-изображений не требуется.
Проверены реальные рендеры Chromium на desktop и 360 px, формы и таблица.
Скриншоты тестов находятся в игнорируемом `frontend/test-results`.

## Проверки

Из `frontend`: `npm ci`, `npx playwright install --with-deps chromium`,
`npm run lint`, `npm run test:ci`, `npm run build`, `npm run test:e2e`.
Эти команды установки и проверки включены в `.harness/checks/frontend.json`.
Harness вызывает их через `frontend/scripts/run_node.py`: он находит установленный
`npm`/`npx` по PATH, включая Windows `npm.CMD`/`npx.CMD`, запускает полный путь
без `shell=True` и сохраняет код завершения. На POSIX используются обычные
исполняемые файлы. Это устраняет отказ Windows `Команда недоступна: npm` без
изменения общего harness, lock-файла или пропуска frontend-проверок.
В PowerShell прямые команды можно вызывать как `npm.cmd`/`npx.cmd`.
Playwright использует собственный Vite на loopback:4173 и отказ при занятом порте,
не подключается к чужому серверу. Unit проверяют HTTP-клиент, версии, страницы,
CSRF, потерю ответа записи и независимость demo; browser-тесты перехватывают API.

Отдельно, из корня, под backend-окружением:

```text
python tests/e2e/ui/check_postgres.py --bin-dir <PostgreSQL bin> --report <report.json>
```

Runner создаёт частный кластер на случайном loopback-порту, применяет миграции,
поднимает настоящую авторизацию/реестр A2, роутеры A3/B1/B2, вычислитель и единственный
worker через общий advisory lock. Chromium входит, создаёт правило, читает
подтверждённый результат и тестовое событие из БД, отключает расписание и выходит.
Последующие GET правил и событий возвращают 401.
Только Syncthing заменён управляемым адаптером. API, worker, кластер останавливаются;
использования рабочих БД/узлов нет. Browser-прогоны запускаются последовательно:
они используют один порт и каталог результатов. Ожидания — по наблюдаемым условиям,
без фиксированного sleep как доказательства результата.

## Передача A4 и ограничения

В принятом `create_app()` ещё не смонтированы роутеры A3/B1/B2 и не внедрён вычислитель
желаемого состояния реестра. Это сборка A4: B3 не меняет `backend/app/main.py` и
не объявляет обычный запуск полностью интегрированным. Пример явной композиции
для проверки — `tests/e2e/ui/application.py`, исключительно тестовый модуль.
Его нельзя использовать как production entry point: там публичные фикстуры.

A4 подключает роутеры rules, executions и events под общим require_admin,
передаёт вычислитель RegistryService, запускает worker и цикл коллектора,
отдаёт dist и API под одним HTTPS origin. Полный UI → настоящий Syncthing → история,
ручная проверка demo-конфигурации и VPS этим результатом не заявляются.
