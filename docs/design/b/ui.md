# План веб-интерфейса B0

Статус: план B3, без утверждения готовности frontend.

## Стек и переносимый запуск

Выбран React + TypeScript + Vite. Версии Node.js, npm и пакетов будут закреплены
в `frontend/package-lock.json` в B3. Поддерживаемый локальный сценарий использует
Node.js LTS и Python 3.12; команды `npm` и `python` выполняются из PowerShell,
Windows Terminal, macOS Terminal или CI без предположения о `/bin/sh`, `bash`,
символе разделителя пути или системной локали. Backend не строит пути
конкатенацией строк: это требование для реализации A/B.

Docker Desktop остаётся воспроизводимой опцией для PostgreSQL и двух
демонстрационных Syncthing на Windows и macOS. Секреты передаются только backend
через переменные окружения/файлы стенда; frontend не получает `api_key`, URL
Syncthing или физические пути.

Dev-сервер использует same-origin proxy к `/api`. Для удалённого backend можно
задать только публичный `VITE_API_ORIGIN` без секретов. Mock-провайдер выбирается
явным флагом сборки и не смешивается с реальным API.

## Экраны и состояния

| Экран | Данные | Обязательные состояния |
| --- | --- | --- |
| `/login` | сессия администратора, CSRF | загрузка, неверные данные, заблокированный backend |
| `/overview` | узлы, папки, последние snapshots | healthy, unreachable, auth error, unknown, stale, пусто |
| `/folders` | папки узла и desired/actual paused | нет узлов, неизвестное состояние, ошибка обновления |
| `/rules` | CRUD одного правила на папку | валидация времени/дней/zone, конфликт версии, отключение без resume |
| `/history` | executions, events, snapshots | пагинация, пробел наблюдений, фильтр периода, пусто |
| `/analytics` | две метрики и дневные точки UTC | `null`/«Нет данных», unknown отдельно, ошибка периода |

В карточке папки всегда рядом показываются `actual_paused`, время наблюдения,
`desired_paused` и признак устаревания. «Расписание отключено» не означает
«папка возобновлена». Кнопка ручного возобновления видна только без активного
правила и показывает результат подтверждения.

## Сетевой слой и доступ

Все управляющие запросы используют cookie-сессию и CSRF-токен в памяти вкладки.
При 401 выполняется переход на `/login`; при 409 показываются конфликт версии и
кнопка повторного чтения; при 503 отображается недоступность без ложного успеха.
Ни один ответ не отображает API-ключ или сырое сообщение Syncthing.

Для экранов с неизвестным или устаревшим состоянием запрещены зелёные индикаторы
успеха. Загрузка, пустой список и ошибка имеют разные представления. Формы
управляются клавиатурой, имеют подписи полей и адаптируются к ширине от 360 px;
цвет не является единственным способом различить статусы.

Примеры DTO и безопасных ответов находятся в `docs/design/b/examples.json`.
