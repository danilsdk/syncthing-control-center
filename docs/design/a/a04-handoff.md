# A0.4 — общие типы и подключение модулей

Реализованы все 30 публичных типов OpenAPI, синхронные протоколы адаптера/Clock,
общие advisory-блокировки и точка подключения worker. Исходный A0 принят
29.10.2026 в PR #2. D-01 r2 и общие исправления аудита ниже проходят отдельный
review продолжения A0; версия публичного документа пока `0.1.0-draft`.
Проверки и ограничения записаны в [журнале A0](../../agent-log/a/A0.md).

## Общие импорты для A и B

| Путь | Содержимое |
|---|---|
| `app.contracts` / `app.contracts.dto` | Все публичные DTO, страницы и enum из OpenAPI |
| `app.contracts.types` | UTC, HH:MM, IANA timezone, ISO-дни/маска и преобразование времени БД |
| `app.contracts.interfaces` | Clock/SystemClock, AdapterFactory/SyncthingAdapter, внутренние наблюдения и AdapterError |
| `app.contracts.locks` | AdvisoryLocks, LockLease, LockBusy/LockLost и единый ключ папки |
| `app.contracts.worker` | WorkerRuntime и WorkerContext |
| `app.api.dependencies` | get_database/get_session, get_clock, get_adapter_factory/get_adapter, get_folder_locks |
| `app.models` | Семь SQLAlchemy-моделей и Base.metadata |

DTO не вычисляют расписание, не запрашивают Syncthing и не меняют БД. Они проверяют
форму и согласованность передаваемых данных: подтверждение applied, снимок версии,
scope наблюдения, временные отметки, метрики и UTC-дни периода. Фактическую
актуальность правила/наблюдения и переходы состояний проверяют B1/B2/A3.

JSON сериализуется через `model_dump(mode="json")` или `model_dump_json()`;
даты всегда UTC `Z`, alias `from` сохраняется. На входе JSON offset вместо `Z`
отвергается; aware datetime из БД приводится к UTC, naive datetime запрещён.
Лишние поля запрещены; boolean/integer не подменяются строками. Неизвестные
наблюдения сохраняются как null. ISO-дни неизменяемы, уникальны и отсортированы.
`days_to_mask`/`mask_to_days` и `hhmm_to_time`/`time_to_hhmm` согласуют DTO с БД.

PATCH использует `changes()` для получения только присланных полей. Явный null
не означает отсутствие поля и отвергается. `RulePatch.apply_to(current)` валидирует
полное слияние с текущим правилом; `expected_version` B1 сверяет отдельно под
блокировкой. `model_copy(update=...)` не заменяет проверку слияния.
Login.password читается через SecretStr только обработчиком A2 и исключён из
repr/сериализации; NodeConnection также скрывает URL и API-ключ.

## Адаптер и события

AdapterFactory.for_node принимает внутренний UUID и возвращает адаптер одного
узла. Его реализация A1/A2 разрешает адрес/ключ из серверной конфигурации;
браузер не передаёт URL. SyncthingAdapter имеет все методы раздела 7 контракта.
Factory.close закрывает принадлежащие ей клиенты.

[D-01, редакция 2](d01-stream-continuity.md) заменяет прежний hash UUID/startTime.
`SystemObservation.from_source` требует StreamAnchor и при создании новой эпохи
учитывает предыдущую. Строки времени сохраняются точно. SourceEvent разделяет
id/global_id, внешний ID папки и безопасный EventPayload. EventBatch допускает
пустой результат, но требует возрастающие позиции и совпадающий SourceCheckpoint
с непустым anchor. Проверка доказательства до/после запроса — задача A1.
A2/resolver передаёт checkpoint из managed_nodes. A3 сохраняет его с событиями
и курсором одной транзакцией под блокировкой узла. Без доказательства нужен
since=0 и новая эпоха; B2 отменяет прежнее подтверждение при смене эпохи.
Контракт остаётся draft до review B0.

AdapterError принимает только фиксированный code. Для чтения write_outcome=null;
для записи по умолчанию unknown. `not_applied` выставляется A1 только при
доказанном отказе. В сообщение не передаются Exception/URL/сырой ответ.

## Общая блокировка папки

`AdvisoryLocks(engine).folder(folder_id, timeout_seconds=3)` используется всеми
изменениями правил и началом команды. UUID хешируется SHA-256 с префиксом
`scc:folder:v1\n`; первые восемь байт дают signed bigint. Python hash не используется.
Коллизия может лишь последовательно выполнить операции разных папок.

Контекст выдаёт LockLease. Защищённые чтения/записи выполняются через
`lease.session()`, которая привязана к удерживающему блокировку соединению.
Вызывающий сервис явно делает commit; выход из session откатывает незавершённое.
Другую get_session/Session из пула внутри защищённой операции использовать нельзя.

Порядок B2: получить блокировку → перечитать правило/условия → сохранить sent_at
через lease.session с commit → вызвать lease.ensure_held() непосредственно перед
HTTP → начать отправку → выйти из блокировки. Это инфраструктура, не готовый B2.
Повторные чтения для подтверждения выполняются по D-04 после отправки.
Потеря соединения/блокировки даёт LockLost и запрещает дальнейшее использование
lease; автоматического переподключения под прежней lease нет. Между PostgreSQL
и HTTP нет общей транзакции; неизвестный исход отправки обрабатывает B2.

Блокировка сохраняется при commit/rollback. finally откатывает незавершённую
транзакцию и подтверждает pg_advisory_unlock; при ошибке физическое соединение
исключается из пула. Lease используется одним потоком, без вложенных сессий.
LockBusy преобразуется HTTP-слоем в 409 operation_in_progress, LockLost — в 503.

## Подключение API и worker

`create_app(settings, database, routers, *, clock, adapters)` принимает ресурсы
явно. Роутеры попадают под `/api` и общую require_admin. До A2 она по-прежнему
возвращает 503 auth_not_configured. Отсутствие адаптера/БД также даёт 503.
Приложение владеет переданными database/adapters и закрывает их при остановке.
В lifespan нет worker, автоматического импорта пакетов B или скрытого scheduler.

```powershell
.\.venv\Scripts\python.exe -m app.main worker
```

Сейчас команда завершится с кодом **2**: B2 runtime и A1 factory ещё не подключены.
Это явный отказ конфигурации, а не успешно работающий исполнитель. A4 подключает
B2 через `run_worker(runtime, settings=..., adapters=...)`. WorkerRuntime.run
получает WorkerContext с БД, Clock, адаптерами и блокировками папок.
Перед каждым циклом/началом внешней записи B2 вызывает context.ensure_active().

run_worker проверяет ревизию БД, удерживает отдельную session-блокировку worker
на всё время runtime и закрывает ресурсы на выходе. Пространство `(int,int)`
отделено от bigint-ключей папок. Второй процесс завершается с кодом **3** до
runtime/команд; недоступность БД/блокировки — **4**, неожиданный отказ — **1**,
обычное завершение — **0**, прерывание — **130**. Минимальный pool worker — 2:
одно соединение singleton, другое для папки; по умолчанию 5.

## Проверки и передача

Установка — [A0.2](a02-runbook.md), миграции/частный PostgreSQL — [A0.3](a03-runbook.md).
Обычный pytest проверяет DTO, протоколы, DI, CLI и отказные сценарии без настоящей БД;
`check_postgres.py` отдельно проверяет схему, commit sent_at под блокировкой,
потерю соединения, чистоту пула и второй worker-процесс. Формы всех 30 типов
автоматически сравниваются с OpenAPI; примеры A0.1 валидируются реальными DTO.

H0 принят в PR #1, исходный A0 — в PR #2. Изменения общего контракта D-01 r2
в этом продолжении требуют собственного review B; прежнее approval не заменяет
их приёмку. Полный validate и CI продолжения A0 прошли, отдельно проверен PostgreSQL.
Реальный адаптер A1, авторизация A2, сбор A3, расписание B1/исполнитель B2 и
развёртывание A4 остаются задачами их владельцев.
