## Проверка спецификации

Из корня репозитория, в отдельном Python 3.12 окружении:

```powershell
python -m pip install -r docs/design/a/requirements-contract-check.txt
python docs/design/a/check_contract.py
git diff --check
```

Проверяются OpenAPI, положительные и отрицательные JSON-примеры, обязательная
защита маршрутов, отметки команд, формулы метрик, границы окон и DST.
Проверка времени — справочный расчёт для фиксированных B0-примеров;
она не является тестом ещё отсутствующего движка B1.
Проверки БД и реального API Syncthing относятся к следующим подэтапам/A1.

## Проверить разработчику B

1. D-01: сессия источника, атомарность курсора, gap/restart без вымышленных событий.
2. D-02: отключение не снимает паузу; ручное resume конфликтует с активным правилом;
   повтор idempotency_key возвращает прежнее намерение.
3. D-03: ISO-дни, пятница 23:00–суббота 02:00, воскресенье–понедельник,
   равные границы, оба вхождения повторившегося часа и отсутствующий час DST.
4. D-04: durable sent_at перед HTTP, advisory-блокировка через commit,
   версия до/после отправки, итог unknown, отсутствие повторного проигрывания sent.
5. D-05: created_at истории отличается от completed_at метрик; scope=node
   исключает влияние числа папок; нулевой знаменатель — null.
6. Подходят ли RulePatch.expected_version, список Execution и маршрут resume
   для B1/B2/B3; достаточно ли общей схемы без миграций в ветке B.
7. Подходят ли Session/CSRF и единый Error для интерфейса.

Вопросы выбора продукта не оставлены без решения. До review это предложения A,
которые B вправе оспорить конкретным сценарием. Отметку «согласовано» добавлять
только со ссылкой на настоящее review.
